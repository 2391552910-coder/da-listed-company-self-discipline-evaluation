## 核心验收场景

| 编号 | 场景与预期 |
| --- | --- |
| T01 | 同一股票存在2023/2024年报，并有其他公司；查询只返回指定公司年度的年报候选 |
| T02 | 指定作用域为空或时点筛选后法规为空；不回退到全库；分别报年报缺失或法规不足 |
| T03 | 原文件被修改、页文本哈希不符或索引模型身份不同；阻止新运行并报告可诊断错误 |
| T04 | 长片段预算不足、跨页法规、OCR片段、DOCX法规；省略记录、逐段位置和来源限制准确 |
| T05 | 命中10条、入上下文6条、正文引用2条；三个数量与关系独立保存，空引用不变为“全引用” |
| T06 | 不存在的引用ID、其他题目的A1、未知事项日期或冲突法规；结构错误/不确定性明确，不被标为人工支持 |
| T07 | 第三章数据为空；页面无虚构指数，HTML/PDF仍导出；0分和null不混淆 |
| T08 | 同请求重复提交、Worker崩溃或API超时；持久化结果不重复覆盖，调用attempt保留，外部调用不声称恰好一次 |
| T09 | Agent预算耗尽、取消请求、服务不可用；有限终止，有失败原因，不无限重试或静默降级 |
| T10 | 新增文档版本并重建索引后，旧评价和旧报告仍定位原证据版本 |
| T11 | 构建后的Nginx访问/api、深层路由刷新、原文件与PDF下载；均通过同源入口 |
| T12 | 人工评分、自动评分、历史缓存与新实跑分组；未运行/失败不冒充质量分数，不夸大Agent收益 |
| T13 | 四维任务有一维失败或缺证；其他维度结果保留，总结和导出明确说明缺项且引用继承可追溯 |
| T14 | 日志、配置快照、导出和提交差异无密钥；绝对本地路径不作为服务端可访问文件参数 |

## 验证层级

1. 单元：来源定位、作用域、预算、引用、状态机等具有业务约束的逻辑。
2. 集成：PostgreSQL事务/迁移/Worker，存储与索引、DTO及路由。
3. 模型适配：固定样例比较研究原型与系统适配器的候选、分数、模型身份、上下文哈希；允许的浮点差异需记录，排序变化不能掩盖。
4. 端到端：真实文档和一次受预算约束的真实API生成，浏览器证据核查及导出。
5. 部署：Windows与服务器分别记录环境、命令、结果及限制。

不以模拟输出证明模型有效，不因语法检查通过就声明系统能运行。对照研究沿用冻结问题与配置，新增数据版本独立建档。

## GitHub 同步约定

- 每个工作包提交重要代码、设计变化、依赖/迁移、可重现检查与简短结果。
- 重要决策更新对应设计文档，阶段状态只在退出条件满足后改变。
- 先读取远端分支最新提交，基于该提交提交并校验；不强推、不覆盖并发修改。
- 当前阶段仅文档及审计脚本可直接同步 main；后续业务变更优先使用开发分支和可审查提交。
- 不提交 .env、密钥、模型权重、大批原始语料、生成调用原件或受限第三章数据；以脱敏版本清单与哈希关联。
- 原始运行、评分、失败恢复视图分别保存，不覆盖历史证据。
